Date: 2026-09-10
Scope: all React components, all hooks, all UI primitives, all Rust backend modules (`lib.rs`, `audio.rs`, `wifi.rs`, `shell.rs`, `settings.rs`, `main.rs`).

## 🔴 Real leaks / hot paths out of place (6)

### H1 — MoonlightView AppsModal re-invokes on every render
- **File:line:** `src/components/MoonlightView.tsx:428-443`, `:773`
- `AppsModal` useEffect deps `[open, host]` where `host` is a fresh `{name, address}` literal built inline in `renderDiscoveredCard`. Every parent re-render (including the per-second elapsed-time ticker at L502-506) creates a new `host` reference → effect re-fires → fresh `moonlight_list_apps` invoke.
- During active streaming with the elapsed clock ticking, this fires every second.
- Impact: redundant IPC every second during active streaming. Can flood Moonlight hosts with `list` requests.

### H2 — AppsView gridRef focus() steals focus from search on every keystroke
- **File:line:** `src/components/AppsView.tsx:493-495`
- `useEffect([query, shortcuts.length])` re-focuses `gridRef.current` on every `query` change. The user types in the search `<Input>` → focus yanked to grid → can lose keystrokes depending on render timing.
- Impact: user-visible breakage of search input. Could be perceived as "search doesn't work".

### H3 — Rust probe_listapps: std::thread::spawn per host, never joined, no inner timeout
- **File:line:** `src-tauri/src/lib.rs:1984-1997`
- For each discovered/paired host, spawns a thread that runs `moonlight list <host>` with no timeout. The outer 8s `recv_timeout` masks the hang, but the spawned thread keeps running indefinitely until moonlight.exe itself returns. On a network with N bad hosts and M scans, N×M orphan threads accumulate.
- Impact: real thread leak. Each orphan holds a `Child` to moonlight.exe. Memory + handle growth over time.

### H4 — Moonlight stream overwrites StreamState.child without killing the prior process; close_app doesn't drain
- **File:line:** `src-tauri/src/lib.rs:1401-1429`, `close_app:2102-2108`, `Destroyed:2492-2494`
- When the user re-streams the same `(host, app)` and the prior child is alive but windowless, the code inserts the new child and drops the old `Child` without killing. `Child::drop` only closes the process handle; moonlight.exe keeps running invisibly.
- `close_app` and `WindowEvent::Destroyed` don't iterate `StreamState` to kill active children either.
- Impact: invisible moonlight.exe processes accumulate during a session. Each consumes memory + a host streaming slot on the remote machine.

### H5 — AudioModal listen() race: listener leaks if modal closes during registration
- **File:line:** `src/components/ui/AudioModal.tsx:97-104`
- `void listen("audio-changed", ...).then((f) => { unlisten = f })` — if the modal closes between `listen()` returning and `.then()` resolving, `unlisten` is undefined at cleanup → listener is registered and never removed. Fires `refresh()` on an unmounted component forever.
- Impact: per rapid open/close cycle during Core Audio notification bursts. Compounds over time.

### H6 — usePowerMenuTrigger pending stranded on consumer unmount
- **File:line:** `src/hooks/usePowerMenuTrigger.ts:13, 31-37`
- `pending` module-level boolean is set true on `openPowerMenu()` but only reset by `resetPowerMenu()` in the consumer's close handler. If the consumer unmounts mid-open, `pending` stays true → next `openPowerMenu()` short-circuits at the pending check. The pubsub becomes permanently dead until app restart.
- Impact: Power menu cannot be re-opened via the pubsub path (Alt+F4 / Immersive-mode close interception). The escape hatch that drives the Power menu is silently broken.

## Most likely "freezing" culprits

If you've experienced freezing on a recent build, the candidates ranked:

1. **H3** (`probe_listapps` thread leak) — most likely cause of slow degradation over time. Repeated scans on a network with bad hosts pile up threads.
2. **H1** (AppsModal re-invoke every second) — directly causes IPC chatter during streaming.
3. **H4** (orphan moonlight.exe + close_app drain) — zombies on close.
4. **I11** (no timeout on tailscale / moonlight subprocesses) — blocking pool exhaustion.
5. **H5** (audio-changed listener leak) — most likely cause of the audio modal feeling slow / stuck if you open/close it a lot.

---

## Suggested fix order

1. **H2** — easy, isolated. Change `useEffect([query, shortcuts.length])` to `useEffect([shortcuts.length])` in `AppsView.tsx`.
2. **H5** — small. Wrap `listen()` in an `AbortController` or capture-unlisten-before-await pattern in `AudioModal.tsx`.
3. **H1** — memoize the `host` object or change the effect deps to `[open, d.name, d.address]` instead of `[open, host]`.
4. **H6** — clear `pending` in a `useEffect` cleanup that watches a "consumer mounted" ref, or refactor to a true pubsub (no pending flag).
5. **H4** — on overwrite, `kill()` the prior child; in `close_app` and `WindowEvent::Destroyed`, iterate `StreamState` and `kill()` all children before exiting.
6. **H3** — wrap the inner `moonlight list` invocation in a `recv_timeout` via a child-thread join with timeout, or push the timeout into the inner `Command` itself. Don't drop the JoinHandle.
7. **I-list** — performance, batched fixes.

## Resolution status

All six H-list items and eight I-list items (I2, I5, I6+I7, I9, I10, I11, I12, I15) were addressed in commits `f429bc1..a12d81d` on top of `2e24ac4`. The build at `Z:\moonblast.exe` (6.66 MB, 2026-09-10 20:35) carries all the fixes.

Items intentionally deferred:

- **I1** (`iconCache` unbounded + `.icons/` disk cache growth) — bigger scope: needs an LRU eviction policy and a size cap on the on-disk cache. Not a leak in the short term; users with hundreds of curated apps over months of use would notice.
- **I3** (`waitForState` uncancellable) and **I4** (`useWifiScan.scan()` no abort) — both need AbortSignal plumbing across the IPC bridge. Functional impact is bounded (each fires ~17 times per closed-mid-connect).
- **I8** (ContextMenu capture-phase scroll closes in-modal menus) — UX question, not a leak. Need a call on which scroll containers should be exempt.
- **I13** (`primary_interface_block` CRLF arithmetic) and **I14** (`connect_with_password` temp-file race) — both touch delicate parsing paths; lower priority than the H-list fixes.
- **I16** (`client_display_raw()` called twice per stream start) and **I17** (auto-immersive setup thread 30s sleep) — cosmetic.
