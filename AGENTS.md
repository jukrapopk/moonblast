# Moonblast — Agent Context

Project memory for working on **Moonblast**, a lightweight Windows Fullscreen Mode / Big Picture-style launcher centered around **Moonlight** streaming. Read this before making changes.

## What it is
- Low RAM/CPU desktop shell (Steam-Big-Picture-like) to launch Windows apps and stream via Moonlight QT.
- **Windows only.** Custom frameless title bar, fullscreen-friendly.
- Goal: minimal, clean, modern dark UI, token-driven styling, no duplication.

## Stack
- **Frontend:** React 19 + TypeScript, Vite, Tailwind CSS v4, Framer Motion, Phosphor `@phosphor-icons/react` (use `weight="bold"` for all icons).
- **Backend:** Rust, Tauri 2 (WebView2).

## Window / fullscreen / Immersive
- Frameless window (`decorations:false` in `tauri.conf.json`) with **`TitleBar.tsx`** (drag region + minimize/maximize/close). TitleBar hides when fullscreen (`App.tsx`).
- `toggle_fullscreen` in Rust also unmaximizes first (avoids a blank strip — the known frameless max→fullscreen artifact). **F11** toggles; `App.tsx` holds `fullscreen` state and threads it to the Power menu button (label/icon flip: Fullscreen ⇄ Windowed).
- **Immersive Mode** (Power menu item — no keyboard shortcut): fullscreen + clean surface. Rust `enter_immersive` forces fullscreen, minimizes other top-level windows (`EnumWindows`), and **kills `explorer.exe`** to suppress the desktop/taskbar; `exit_immersive` restarts it (guarded by the `EXPLORER_KILLED` `AtomicBool`). The shell is also restored on `close_app` and on window `Destroyed` (`on_window_event`). **TopBar stays visible** — suppression targets the *outside* (desktop/background), not the app's own chrome. Alt+F4 / taskbar-Close while in Immersive is intercepted and routes to the Power menu (single pubsub in `usePowerMenuTrigger`); Escape closes whatever modal is open but does **not** exit Immersive.
- **Auto Immersive Mode** (`fullscreen.auto_immersive`, `src-tauri/src/shell.rs`) — **one** switch that both registers Moonblast as the Windows shell and enters Immersive Mode at sign-in. Sets the **per-user** `HKCU\…\Winlogon\Shell` value so `userinit.exe` launches Moonblast instead of `explorer.exe`. Because it's the user's own hive it needs **no elevation — no UAC prompt, ever** (the HKLM equivalent would). Explorer then never starts *at all* rather than starting and being killed, so there's no desktop/taskbar flash, and `Run`/`RunOnce` + the Startup folder never run (Explorer is what processes them) — background apps are suppressed for free. There is no separate "Start with Windows" toggle — the stub is the only boot-launch path, so there's nothing to coordinate and no risk of double-launching Moonblast at sign-in.
  - **Toggling never enters Immersive Mode**; it only arms the next sign-in. Winlogon points at a **stub** (`Moonblast.exe --shell`, intercepted in `main.rs` before any Tauri setup) which launches the launcher with `--autostart` — and *that flag* is what triggers Immersive Mode (`booted_as_shell` command). The decision is made once in `App.tsx` the moment settings hydrate, keyed only on `ready`.
  - The stub runs the launcher, waits, and afterwards guarantees a desktop (`ensure_desktop` → Explorer unless `GetShellWindow` says one is up). On **clean exit** (user closes Moonblast via the Power menu → `close_app` → `app.exit(0)`, exit code 0) the stub itself exits so Task Manager doesn't show a no-window stub for the rest of the session — Windows falls through to the HKLM default shell on next sign-in. On **abnormal exit** (panic, OOM, spawn failure — any non-zero exit) the stub parks as the session's shell process in a 2-second `ensure_desktop` loop, so a crash still leaves a working desktop. The 3-strike counter (`MAX_SHELL_CRASHES`) bails the takeover out entirely on persistent crashes.
  - Escape hatch: 3 consecutive fast crashes (`ShellCrashCount` in `HKCU\Software\Moonblast`, cleared 30s into a healthy run) restore the normal shell automatically. The previous `Shell` value is backed up to `OriginalShell`/`OriginalShellSet` so restore puts back "absent" vs. an explicit value correctly. To recover non-emergently, toggle Auto Immersive Mode off in Settings — the setting only arms the *next* sign-in, so it never yanks the user out of Immersive Mode on the spot.
  - `setup` reconciles intent against reality: if the setting is on but the registry **isn't** armed, a rescue already fired — it clears `auto_immersive` (`settings::disable_auto_immersive`) rather than silently re-arming. If it *is* armed, it only refreshes the exe path so moving/updating the app can't strand a stale entry.
  - `exit_immersive` starts Explorer when the desktop is replaced (nothing for `suppress_shell(false)` to restore, since Explorer never ran).
  - **Legacy cleanup.** `setup` calls `shell::cleanup_legacy_run_key()` on every boot to delete a stale `HKCU\…\Run\Moonblast` value left over from the previous build that had a "Start with Windows" toggle. Without this, upgrading users would briefly see two Moonblast.exe processes at sign-in (one from the Run key, one from the stub) until the value is removed manually. Idempotent — "not found" is success.
- **Console windows**: child processes (`powershell Get-StartApps`, `taskkill`, `tailscale`, `shutdown`) are spawned with `CREATE_NO_WINDOW` (`creation_flags(0x08000000)`) so no console flashes.

## Layout & navigation
- `TitleBar` → `TopBar` (icon-only nav: 🗂 Apps, 🖥 Moonlight on left; ⚙ Settings, ⏻ Power on right; **system status on the far right**: 🕒 clock chip + battery + WiFi icon buttons, all via the shared `TopBarButton`) → `main` scroll area.
- Views: **apps | moonlight | settings**. The Moonlight view has its own **Machines / Settings** segmented sub-tab. Wrappers in `App.tsx` use `p-8` on all sides (no `h-full`, so bottom padding works when scrolled).
- **`PageShell.tsx`** is the shared layout (title/subtitle/actions/tabs/children, `max-w-6xl`). Every page uses it.
- Tabs via shared **`ui/Segmented.tsx`** (variants: `tabs` pillar, `value` picker).
- View switching: there is no keyboard shortcut to cycle top-level views — `Tab` / `Shift+Tab` follow native browser focus traversal, so keyboard users reach form controls and modal buttons in document order. Switch views by clicking the TopBar nav buttons (or by Tab into the TopBar then Left/Right). The last non-settings view is persisted (`general.last_view`) and restored on next launch. Settings never overwrites `last_view`, so the app always boots into Apps or Moonlight.

## Keyboard
- **Input pipeline (`src/input/`)** — single global controller at the app root:
  - `spatialNav.ts` — typed wrapper around `@bbc/tv-lrud-spatial` (DOM-rect-based directional nav). Library accepts `keyCode` numbers at runtime; the wrapper lets us pass `KeyboardEvent.key` strings.
  - `useSpatialController.ts` — owns one `window` keydown listener. **Tab is not intercepted** — native browser focus traversal handles form controls / buttons / links in document order, including inside modals and the Settings page. Arrow keys route through `moveFocus(current, dir, scope)` where `scope` is the active focus trap (modal panel). Escape and Enter go to a LIFO stack of registered handlers (modals + menus push on open, pop on close). Text inputs / selects / range sliders are excluded so their native arrow semantics survive.
  - `useFocusTrap(panel, opts)` — installs Escape + Enter handlers, sets the spatial scope to the panel (arrows can't escape), auto-focuses the first focusable (or `opts.initialFocus` selector), and restores on cleanup.
- **Keyboard:** `F11` fullscreen, **Tab / Shift+Tab** traverse focusables in document order (form controls, modal buttons, etc.) via native browser focus traversal — no custom interception, **Arrow keys** move focus spatially (no per-page keydown handlers — the LRUD library handles all directional nav by measuring candidate rectangles; `data-lrud-scope-lock` attributes constrain which axis stays in which container), `Enter`/`Space` activate the focused button (native button activation), `Esc` closes the topmost modal/menu, **and `Esc` / `Up` (when no modal/menu is open and no vertical lock applies above focus)** — focus the TopBar button for the currently-active view (`[data-active-view]` attribute set by `TopBarButton`). Both keys serve as a "jump back to nav" escape hatch from anywhere on the page. Immersive Mode is entered from the Power menu only (no keyboard shortcut); `Esc` closes whichever modal is open but does **not** exit Immersive Mode.
- **Spatial containers** — anywhere that wants arrows to stay scoped is marked `.lrud-container` (or is a `<nav>` / `<section>`; LRUD picks those up natively). Containers include: every `Section` in Settings, every `PreferenceGroup`, the TopBar (one container wrapping left nav + status chips + right nav + Power), the Apps grid, the Moonlight host list, each HostCard's action-button cluster, the AppsModal app list, the SteamGridModal icon grid, the ContextMenu panel, every Modal panel (auto via `useFocusTrap`). The TitleBar window controls (Minimize / Maximize / Close) and the Apps page's "Search apps" filter input are **not** focusable via keyboard — they carry `tabIndex={-1}` and stay mouse-only. Window-management actions belong in the Power menu (a regular TopBar focusable); search is mouse-only because Left/Right inside a text input always means caret movement (universal input convention) and the search row has nothing focusable to its left. Containers store last-focused child in `data-focus` so coming back to a section restores focus rather than dumping it to the first row. The library also tracks `data-focus` on the focused element's id — so give buttons stable `id`s where container persistence matters.
- **Directional scope locks** (`data-lrud-scope-lock="horizontal|vertical|all"`) — a per-container attribute that locks one axis of arrow movement. The TopBar sets `data-lrud-scope-lock="horizontal"` so Left/Right stay inside the topbar (Apps → Moonlight → Display → Wifi → Battery → Audio → Settings → Power, then no-op on either edge) while Up/Down escape into the page. The controller's arrow handler walks up from `document.activeElement` looking for a lock ancestor whose direction set matches the pressed arrow; on match, the LRUD library's fallback `getAllFocusables(scope)` is constrained to that container. Modal panels use the equivalent via `setSpatialScope(panel)` from `useFocusTrap` (full lock + Escape + Enter handlers + restore-on-close).
- **`.lrud-ignore`** — class for elements that should be skipped by the spatial library. Note: marking a wrapper `lrud-ignore` also filters out its focusable children (the library's `ignored.contains(node)` check). Use it only on standalone non-wrapper elements that match `[tabindex], a, input, button` themselves, NOT on `<motion.div>` / wrapper divs.
- **Apps grid** is now spatially navigable: arrow keys move to the nearest tile in each direction. The library computes the right neighbor from screen rectangles, so the grid stays usable at any column count (the responsive `grid-cols-4 sm:5 lg:6 xl:8` works without manual column logic). Focused tile gets the visual lift via `:focus-visible` (replaces the old `focusIdx`-driven `bg-accent-soft` class).
- **Modal focus trap** (WAI-ARIA dialog semantics): on open, focus moves to `initialFocus` (or the first focusable inside the panel); while open, arrows can't escape the panel via `setSpatialScope(panel)`; on close, focus restores to the element that was focused before the modal opened. Multiple modals stack via the LIFO Escape handler — the inner modal's Escape runs first.
- **ContextMenu** is now keyboard-navigable: opens focused on first item, Up/Down cycles via the spatial library (the menu is `.lrud-container`), Enter activates (the button's native click fires), Escape closes, focus restores to the trigger element.
- **App-level context menu** (`App.tsx`): right-click anywhere not handled by a more specific menu shows a generic **Refresh** menu (reload the page). Specific views (`AppsView`, `MoonlightView`, `TitleBar`) own their own per-element right-click menus. `Input` fields install their own Undo/Cut/Copy/Paste/Select-All menu on right-click.

## Moonlight integration (IMPORTANT — current architecture)
Streaming/pairing is done by **driving the Moonlight QT client via its CLI**, NOT by reimplementing the protocol in-process. Keep it that way.
- The user selects the **Moonlight install folder** in Settings → Integrations; it's validated to contain `moonlight.exe`/`moonlight-qt.exe` (`validate_moonlight_dir`).
- Rust commands in `lib.rs` run the exe:
  - `moonlight_list_apps(host)` → `moonlight list <host>` (action is `list`, not `listapps`).
  - `moonlight_pair(host)` → `moonlight pair <host>` (shows Moonlight QT's own pairing UI).
  - `moonlight_stream(host, app)` → `moonlight stream <host> <app>`. "Desktop" streams the host's Desktop app. The launcher tracks running stream child processes in a `StreamState` keyed by `host\u{1f}app` so a second click doesn't spawn a duplicate window for the same host+app.
  - `moonlight_quit(host, app)` → spawns `moonlight quit <host>` on a **dedicated `std::thread`** with `CREATE_NO_WINDOW` (no Qt dialog flash) and an 8 s bounded wait so a hung CLI never stalls the IPC. In parallel it `Child::kill` + `bounded_wait(5s)` on the local moonlight.exe window Moonblast launched for `(host, app)` so it doesn't linger. The CLI handles Sunshine's pinned cert internally, so we don't have to drive the HTTPS `/cancel` endpoint ourselves.
- **Host discovery:** `discover_hosts()` (Rust) browses `_nvstream._tcp.local.` via `mdns-sd` for ~3s, then probes each host with `moonlight list <host>` to classify paired/unpaired. The whole scan runs on `spawn_blocking` so it never freezes the UI.
- **Paired hosts:** `moonlight_paired_hosts()` reads Moonlight QT's own QSettings store (Windows registry `HKCU\Software\Moonlight Game Streaming Project\Moonlight\hosts\*` for normal installs, or `Moonlight.conf` next to `moonlight.exe` for portable installs) — a host is paired if it holds a pinned `srvcert`. No CLI exists for this; Rust reads the store directly.
- **Saved-machine reachability:** `moonlight_probe(host)` does a 1.5s TCP probe to ports 47984 / 47989 (so Tailscale `*.ts.net` hosts work too) and a `moonlight list` check for pairing — used to show saved machines as **Online / Offline** without depending on mDNS.
- **Event-driven pairing refresh** (`moonlight_pair`): Rust waits for the `pair` process to exit, then emits a `pair-complete` event; the frontend rescans once (no polling).
- Same-PC local connect works via `127.0.0.1`.
- **The Moonlight page shows a single unified list, not three.** `MoonlightView` merges mDNS discovery, the paired registry, and the user's `settings.machines` into one `HostEntry[]` keyed by **case-insensitive name** (not address). Address precedence: **saved > paired > discovered**. The saved address wins because that's the manual override the user added — typically a Tailscale `*.ts.net` hostname or a remote IP for when the host's LAN IP has changed. Two sections are rendered:
  - **Paired** — `entry.paired === true`. A `Saved` badge shows when the saved address differs from the paired record's address (so the user knows the active address isn't the paired record's). Stream Desktop / Apps are gated on `paired AND reachable`.
  - **Other hosts** — `entry.paired === false && entry.discovery === true`. Only shows Pair (gated on reachable).
  - **Per-host right-click menu** mirrors the card buttons and adds two independent destructive actions: **Forget pairing** (drops the cert from Moonlight's store; doesn't remove the saved address) and **Remove saved address** (drops the override; the host falls back to its paired or discovered address if any).
- **Moonlight → Video → HDR** has a `Follow Global HDR` checkbox (default `true`) above the HDR toggle. When on, the HDR toggle is read-only — the thumb mirrors the OS-level display HDR state via `hdr_status()` so the user sees what the stream will do, but can't click it. Rust `moonlight_flags()` resolves HDR at stream start from `hdr::hdr_status().enabled` (not from `prefs.hdr`) so the stream always tracks whatever the display is doing at that moment. When the checkbox is off, the HDR toggle becomes a normal per-stream toggle backed by `prefs.hdr`. The follow state is persisted as `moonlight.hdr_follow_global` (Rust struct field with `#[serde(default = "default_true")]` so existing `settings.json` files upgrade cleanly).
  - **Visual sync of the disabled toggle.** Rust `set_hdr` IPC emits a `hdr-changed` event with the post-write `HdrStatus` after every successful write. `MoonlightSettings` listens for that event and re-reads `hdr_status()` — so toggling HDR in the Display modal updates the read-only HDR toggle in Moonlight settings within milliseconds without a remount. To catch OS-side HDR flips (Windows Settings, OEM hotkey, system policy), `MoonlightSettings` also re-reads on `window.focus` and `visibilitychange → visible`. The actual stream is always correct regardless: `moonlight_flags()` re-resolves at spawn time, so a stale visual indicator can never stream the wrong value.

## WiFi integration
- **Status chip in the TopBar** + **picker modal** (one tap to connect/scan/disconnect). Two visual states per network row: **Connected** (Disconnect button) or **Saved / unknown** (whole row is the action, click anywhere). Radio on/off lives in Windows Wi-Fi settings — open the OS Wi-Fi pane yourself if you need to toggle it; the modal stays in-app for everything else.
- **Rust `wifi.rs` is netsh-based**, not wlanapi. Read-side wlanapi calls (`WlanEnumInterfaces` / `WlanQueryInterface` / `WlanGetAvailableNetworkList`) return `ERROR_NOT_FOUND` (1168) inside a long-lived Tauri process even though the same calls work from `cargo run` — the wlan service's per-client cache goes stale. So:
  - `wifi_current` shells out to `netsh wlan show interfaces` and parses `State` / `SSID` / `Signal` / `Authentication` / `Radio status`. Returns `Some(...)` whenever an adapter exists — with `radio_on` false when the radio is off (chip shows `WifiX`, still clickable) — and `null` when there's no adapter at all (chip hidden on desktops / VMs). Note `Radio status` spans two lines when HW/SW differ (`Hardware On` + continuation `Software Off`); the radio is on only when both are on.
  - `wifi_scan` calls `WlanScan` (the wlanapi write opcode, which works in the Tauri process), sleeps ~2.5s to let the driver populate the visible-network cache, then `netsh wlan show networks mode=bssid` and parses `SSID N` blocks. Each block's BSSIDs give the strongest `Signal` (max), `connected` flag (vs. `netsh_current_connection`), and best `gen` (`Radio type` line → 4/5/6/7). The first `netsh show networks` call returns only the connected network; the second call after the sleep returns the full visible list — that's how the cache populates. `wifi_scan` is registered as `async` and dispatched via `tauri::async_runtime::spawn_blocking` so other Tauri commands (chip reads, connect, disconnect) interleave normally while a scan is in flight.
  - `wifi_connect(ssid)` → `netsh wlan connect name=<ssid>`. Works for open networks and any network the user has connected to once (saved profile).
  - `wifi_connect_with_password(ssid, password, auth)` → builds a temporary WLAN profile XML, registers it via `netsh wlan add profile filename=...`, then `netsh wlan connect`. The profile sticks around after connect, so the SSID is "Saved" in the picker next time. Supports WPA2-Personal / WPA3-Personal / WPA-Personal / WEP; Enterprise and unknown auth kinds return `Err("...not supported in-app; open Windows Wi-Fi settings")` and the modal falls back to launching `ms-settings:network-wifi`.
  - `wifi_disconnect()` → `netsh wlan disconnect`. No-op if already disconnected.
  - `wifi_forget(ssid)` → `netsh wlan delete profile name=...`. Idempotent ("not found" = already forgotten).
- **`useWifi` (hook)** is event-driven, not a timer. Reads on mount, on window `focus`, on `visibilitychange` → visible, and on an explicit `refresh()` call from the parent. The implementation is a thin wrapper over the shared `useDebouncedRead` hook — back-to-back events collapse into one IPC within a 2s window via `inFlight` (the in-progress Promise — concurrent callers share the same read) and `lastReadAt` (skip if a read completed within 2s). The chip and the modal share a single `useWifi` instance via prop drilling (`currentSsid` + `radioOn`); on `wifiOpen` change the parent calls `refreshWifi()` so the chip reflects any change the user just made in the modal. When the radio is off the modal skips the auto-scan, shows a "Wi-Fi is off" hint, and disables Rescan; returning from OS Settings fires focus → parent refreshes → off→on auto-scans.
- **WiFi picker modal** (`src/components/ui/WifiModal.tsx`):
  - **Password form in-app.** Clicking a secured network with no saved profile replaces the list with a single-field password form (show/hide eye toggle, Enter to submit, Cancel/Back). No more bouncing to the Windows Wi-Fi settings app.
  - **Per-row in-flight UI.** Each row has its own `busy` state (`{ ssid, kind: "connect" | "disconnect" | "forget" } | null`). The busy row shows an inline spinner + "Connecting…" / "Disconnecting…" / "Forgetting…" subtitle; all other rows are disabled via a separate `anyBusy` prop. The connected row dims to opacity-40 during disconnect to match the connecting treatment.
  - **Disconnect button** on the connected row is `variant="ghost"` (no border) and hides during the disconnect operation. The "Disconnecting…" subtitle carries the state.
  - **Generation badge.** A small number (4/5/6/7) sits at the bottom-right of the signal icon, mapped from the netsh "Radio type" line per BSSID.
  - **Row context menu.** Right-click mirrors left-click (Connect / Disconnect, text-only) plus **Forget** (danger, Saved rows only) which deletes the stored profile via `wifi_forget` with a `Forgetting…` in-flight state.
  - **Footer.** Rescan button on the left (disabled while the radio is off). Radio on/off lives in the OS — open Windows Wi-Fi settings yourself if you need to toggle it; the modal stays in-app for everything else.
- **Safe state reset on close.** Because `Modal` wraps its children in `AnimatePresence` (children stay mounted through the exit animation), a `useEffect([open])` clears `busy` on close so a fresh open doesn't show a stale "Connecting…" / "Disconnecting…".

## Diagnostics (file logger + panic hook)
- **`src-tauri/src/logging.rs`** — a single-file append-only logger at `%LOCALAPPDATA%\com.moonblast.app\moonblast.log`, truncated on every cold start unless `MOONBLAST_LOG_PRESERVE=1` is set. `logging::init(data_dir)` is called from `run()` before `tauri::Builder::default()`.
- `moonblast_log!(...)` macro formats and writes one line. Use it liberally at the entry/exit/error of any non-trivial Tauri command — especially around lifecycle-sensitive paths (`moonlight_stream`, `moonlight_quit`, `close_app`, the window-event handlers). The cost is negligible (one `writeln!` per call, OS-buffered).
- **Panic hook** is installed in `logging::init`. Any panic on any thread writes `PANIC at <file>:<line>: <payload>` + a forced backtrace to the log right before unwind, so even a release-mode process death leaves evidence on disk. The default Rust panic hook prints to stderr, which is invisible in a `windows_subsystem = "windows"` release — the replacement is necessary.

## Display / HDR
- **`src-tauri/src/hdr.rs`** — detect + toggle Windows Advanced Color (HDR) on the first active display path via `DisplayConfigGetDeviceInfo` / `DisplayConfigSetDeviceInfo` with `DISPLAYCONFIG_GET_ADVANCED_COLOR_INFO` / `DISPLAYCONFIG_SET_ADVANCED_COLOR_STATE` packets. The GET u32 packs four 1-bit flags (`advancedColorSupported`, `advancedColorEnabled`, `wideColorEnforced`, `advancedColorForceDisabled`) — see the module doc comment for verified bit semantics on this driver. The SET `value` bit 0 is `enableAdvancedColor` per the SDK docs + verified by probe.
- Any failure (no active path, driver doesn't support HDR, pre-Win10-1903, etc.) folds into `{ supported: false, locked: false, enabled: false }`. Exposed as `#[tauri::command]`s `hdr_status` / `set_hdr`.
- Uses the **`windows` 0.61 typed crate** (`Win32_Devices_Display` feature) — `windows-sys` 0.59 (the rest of the codebase) doesn't expose `DisplayConfigGetDeviceInfo` / `QueryDisplayConfig`. The two crates coexist (distinct namespaces); Cargo.toml has both.
- **Settings → Display → HDR** row: `Toggle` bound to `hdrStatus.enabled`. The row is always shown — the description changes ("Checking" / "Couldn't detect…" / "This display doesn't support HDR." / "Locked by Windows color settings…" / "HDR is on/off.") and the toggle is `disabled` whenever the read failed, the panel doesn't support HDR, or the OS has locked the toggle. Disabled toggles render as off (visual only) per the universal convention.
- **`src-tauri/src/display.rs`** — multi-monitor aware. `list_monitors` enumerates GDI adapters via `EnumDisplayDevicesW(NULL, i, ...)`, then for each adapter fetches monitor 0 (`EnumDisplayDevicesW(adapter_name, 0, ...)`). Multi-head GPUs that report the same physical monitor under several `\\.\DISPLAYn` aliases (e.g. a laptop's internal panel exposed as DISPLAY1 + DISPLAY2) collapse to one entry via a `DeviceID` (`MONITOR\XXX\...`) dedupe set. **Friendly names** come from `WmiMonitorID.UserFriendlyName` via PowerShell (`CREATE_NO_WINDOW`) — `DISPLAY_DEVICEW.DeviceString` only returns "Generic PnP Monitor", but the EDID-derived model name (e.g. "BenQ EX2780Q", "HISENSE") lives in the WMI monitor-identity classes. We extract the EDID vendor code (`BNQ7F76` etc.) from each monitor's `DeviceID` and look it up in the WMI map. Falls back to the GDI `DeviceString`, then the GPU adapter name when WMI is unavailable. Mode enumeration / apply use `EnumDisplaySettingsExW` and `ChangeDisplaySettingsExW` parameterized by device name (no flags = dynamic mode change, reverts on sign-out / reboot). Pending revert is keyed by device name so concurrent changes on different monitors don't stomp each other.
- **Settings → Display → Monitor** row: `Select` listing every connected monitor with `(primary)` / `— disabled` suffixes. Auto-picks the primary on first load, falls back to the primary if the selected monitor disconnects, and re-fetches modes + current whenever the user picks a different one. Matches the Windows Settings "Rearrange your displays" model — one row per physical display, not per GDI head.
- **Settings → Display → Resolution** row (`ResolutionPicker`): two `Select` dropdowns (resolution, refresh) + Apply, all keyed to the selected monitor. Picking a new resolution opens a confirmation modal with a 10-second auto-revert countdown and Keep/Revert buttons — same UX shape as Windows' built-in keep-changes dialog but our own UI (no `ms-settings:` handoff per the universal no-handoff rule). If the user leaves Settings with a change pending, the page-level `useEffect` cleanup reverts only that monitor's pending change. Disabled toggles / Apply button render as off (visual only) when no modes loaded yet or the monitor is disabled.

## Battery integration
- **Battery chip in the TopBar** (left of WiFi) + **`src/components/ui/BatteryModal.tsx`**. Click the chip → modal opens with STATUS (big percent + horizontal fill bar, red ≤10% / accent otherwise, plus time-remaining or time-to-full) and POWER SOURCE (text-only "Wall power" / "Battery"; no icon to avoid duplication with the chip). No footer action — the modal is read-only.
- **Rust `battery` command** (`src-tauri/src/lib.rs`) reads Win32 `GetSystemPowerStatus` and returns `{ percent, charging, pluggedIn, timeRemainingSec }`. `percent` is -1 when the OS reports unknown (chip falls back to `BatteryWarning`). `charging` uses the hardware `BatteryFlag & 0x08` bit so a fully-charged laptop on the charger shows "Plugged in", not "Charging". `pluggedIn` mirrors `ACLineStatus`. `timeRemainingSec` is `null` when `BatteryLifeTime == -1` and `0` when the OS knows there's no estimate yet (charging with no rate).
- **Realtime updates** without Rust push events: `src/hooks/useBattery.ts` is also a thin wrapper over `useDebouncedRead`, with a **5s background poll** plus refresh on `focus` and `visibilitychange` → visible. The modal adds its own **2s refresh** while open so the percent and time-remaining tick down live. The OS itself only updates `SYSTEM_POWER_STATUS` at ~1Hz, so faster polling would just return duplicate values; the 5s cadence matches that.
- **Critical flash**: `motion.div` infinite opacity loop (1 → 0.45 → 1, 1.4s, `easeInOut`) when on battery and ≤5% (below the static `danger` red threshold so the two states never stack).
- **Tooltip** doubles as aria-label: `"Charging · 73% · 48m to full"` / `"On battery · 73% · 1h 42m left"`.
- **Full-charge icon fix**: at exactly 100% the bold-outline `BatteryFull` silhouette has no internal bar segments left (they collapse into the outline at full charge), so the dimmed 40%-opacity base treatment reads as "powered-down chip" / muted glyph. At full charge `BatteryFlag & 0x08` is off (hardware reports "fully charged, not accepting current"), so the `BatteryCharging` overlay is absent — the dimmed outline stands alone → mute. Branch on `percent >= 100` and render `BatteryFull` with `weight="fill"` (solid silhouette) at 100% opacity instead. Charging overlay behavior unchanged.

## Display integration (chip + modal)
- **Display chip in the TopBar** (rightmost — `Monitor` glyph, `show_display` toggle in Preferences) + **`DisplaySettingsModal`** in `SettingsView.tsx`. Click the chip → modal opens; `Escape` or overlay click closes.
- **Layout:** Monitor (Select) → HDR (Toggle) → Resolution (Select) → Refresh rate (Select). Single `max-w-lg` Modal; `Settings` page-level Display section is just a button that opens this modal.
- **Loading chips**: every row that does an IPC roundtrip renders a small spinner chip (`ui/LoadingChip.tsx` — `ArrowsClockwise animate-spin` + label, `h-9` to match `Select`) while loading. Empty dropdowns used to flash for 300-700ms during PowerShell / WMI calls — now a labeled spinner instead. State uses the 3-state `undefined` / `null` / `T` pattern: `undefined` = loading, `null` = error, value = loaded. `null` means error or "no value"; `undefined` means we haven't tried yet.
- **Monitor enumeration (`src-tauri/src/display.rs`):** `EnumDisplayDevicesW(NULL, i, ...)` for adapters, then `EnumDisplayDevicesW(adapter_name, 0, ...)` for monitor 0. Multi-head GPUs that report the same physical monitor under several `\\.\DISPLAYn` aliases (e.g. a laptop's internal panel exposed as DISPLAY1 + DISPLAY2) collapse to one entry via a `DeviceID` (`MONITOR\XXX\...`) dedupe set. **Friendly names** come from WMI `WmiMonitorID.UserFriendlyName` via PowerShell (`CREATE_NO_WINDOW`) — `DISPLAY_DEVICEW.DeviceString` only returns "Generic PnP Monitor", but the EDID-derived model name (e.g. "BenQ EX2780Q", "HISENSE") lives in the WMI monitor-identity classes. We extract the EDID vendor code (`BNQ7F76` etc.) from each monitor's `DeviceID` and look it up in the WMI map. Falls back to the GDI `DeviceString`, then the GPU adapter name when WMI is unavailable.
- **Mode apply (`display.rs`):** `EnumDisplaySettingsExW` for enumeration, `ChangeDisplaySettingsExW` for apply (no flags = dynamic mode change, reverts on sign-out / reboot). Pending revert is keyed by device name so concurrent changes on different monitors don't stomp each other. The frontend keeps a 10-second keep/revert modal; page-level `useEffect` cleanup reverts only that monitor's pending change if the user leaves Settings.
- **HDR (`src-tauri/src/hdr.rs`):** `DisplayConfigGetDeviceInfo` / `DisplayConfigSetDeviceInfo` with `DISPLAYCONFIG_GET_ADVANCED_COLOR_INFO` / `DISPLAYCONFIG_SET_ADVANCED_COLOR_STATE` packets against the first active display path. The GET u32 packs four 1-bit flags (`advancedColorSupported`, `advancedColorEnabled`, `wideColorEnforced`, `advancedColorForceDisabled`) — see the module doc comment for verified bit semantics on this driver. The SET `value` bit 0 is `enableAdvancedColor` per the SDK docs + verified by probe. Any failure (no active path, driver doesn't support HDR, pre-Win10-1903, etc.) folds into `{ supported: false, locked: false, enabled: false }`. Uses the **`windows` 0.61 typed crate** (`Win32_Devices_Display` feature) — `windows-sys` 0.59 doesn't expose `DisplayConfigGetDeviceInfo` / `QueryDisplayConfig`. The two crates coexist (distinct namespaces); Cargo.toml has both.
- **Frontend (`DisplaySettingsModal` in `SettingsView.tsx`):**
  - On modal open: fires `list_monitors`, `hdr_status` in parallel; `display_modes` / `current_display` fire once the monitor list resolves and a primary monitor is auto-selected. On monitor switch, modes reload for the new device.
  - `ResolutionPicker` accepts a `loading: boolean` prop so the parent can pass `displayModes === undefined` to drive the loading chip; both Resolution and Refresh rows swap their `Select` for a `LoadingChip` while loading.

## Audio integration
- **Speaker chip in the TopBar** (right of WiFi) + **mixer modal** (`src/components/ui/AudioModal.tsx`): output-device picker, main volume slider + mute, per-app sliders (grouped by exe like the Windows mixer) each with mute + reset-to-max, and a "Reset all" button (every app channel to max + unmuted). The modal covers every per-device + per-app control Moonblast needs; there is no in-app handoff to Windows' Sound panel. No Refresh button, no polling — see push model below.
- **Rust `audio.rs` is Core Audio COM via hand-declared vtables** (`windows-sys` 0.59 ships the MMDevice constants but no interfaces — same situation as `IApplicationActivationManager` in `lib.rs`). Only vtable layout matters; unused trailing slots are `usize`. COM pointers use a `ComPtr` RAII wrapper (Releases on drop) so early `?` returns can't leak. All commands are `async` + `spawn_blocking`; no elevation needed (per-user audio policy).
  - Devices: `MMDeviceEnumerator` → `EnumAudioEndpoints(eRender, ACTIVE)` + `GetDefaultAudioEndpoint`; friendly names via `IPropertyStore` + `PKEY_Device_FriendlyName` (`{A45C254E-DF1C-4EFD-8020-67D146A850E0}`, pid 14 — read `VT_LPWSTR` at PROPVARIANT offset 8, then `PropVariantClear`).
  - Default switch: undocumented `IPolicyConfig::SetDefaultEndpoint` (slot 13) for all three roles, like the Sound panel's "Set as Default Device".
  - Main mixer: `IAudioEndpointVolume` on the default endpoint (scalar ↔ 0–100).
  - Apps mixer: `IAudioSessionManager2` → session enumerator; skips expired / system-sounds / pid-0 sessions; process names via `OpenProcess` + `QueryFullProcessImageNameW`; rows grouped by lowercase exe, sets apply to all of the app's sessions.
  - **GUIDs must come from the Windows SDK headers** (`um/mmdeviceapi.h`, `um/audiopolicy.h`, `um/endpointvolume.h`, `um/functiondiscoverykeys_devpkey.h`) — notably `IID_IMMDeviceEnumerator` ends `...3617E6`, not `...36636E`. A wrong IID fails as `E_NOINTERFACE`/`CLASSNOTREG` even though the CLSID resolves, which is indistinguishable from broken COM without header ground truth.
  - **Push model for master, read-on-open for apps.** Two process-lifetime COM callback singletons (static vtables, refcount no-ops) funnel into one `audio-changed` Tauri event: `IAudioEndpointVolumeCallback` (master volume/mute, incl. volume keys) and `IMMNotificationClient` (device add/remove + default switches). `ensure_watch` (called atop the read commands) registers both idempotently and re-registers on default-device switches; registrations live in a `WATCH` static holding the endpoint/enumerator `ComPtr`s + `AppHandle` (all use sites are MTA). The apps mixer is read fresh on every modal open (per-session push via `IAudioSessionEvents` was tried and dropped — callbacks registered but never delivered).
- **`useAudio` (hook)**: `useAudioMaster` for the chip (mount / focus / visible / explicit refresh + `audio-changed` events). The modal subscribes while open. Slider drags invoke fire-and-forget (no await per tick); mute/reset await + refresh. Parent refreshes the chip on modal close.
- Shared **`ui/Slider.tsx`** primitive (native range input tinted with `accentColor: var(--color-accent)` — arrow keys work natively).

## Settings (persistent)
- **Rust `settings.rs`** — typed serde `Settings` with `version`, `general` (last_view), `integrations` (moonlight_folder, moonlight_enabled, apps_enabled, steamgrid_key), `moonlight` (full streaming-pref set: resolution, refresh_rate, bitrate, codec, display_mode, video_decoder, audio_config, vsync/hdr/hdr_follow_global/yuv444/frame_pacing/keep_awake/quit_after/game_optimization/audio_on_host/mute_on_focus_loss/multi_controller/background_gamepad/swap_gamepad_buttons/absolute_mouse/mouse_buttons_swap/reverse_scroll_direction/capture_system_keys, packet_size, fps_overlay, aspect_ratio), `fullscreen` {suppress_explorer, auto_fullscreen, auto_immersive}, `customization` {show_time, show_date, show_display, show_wifi, show_battery, show_audio}, `machines[{name,address}]`, `app_shortcuts[{name,path,source,kind,display_name,custom_icon,use_desktop_icon,steamgrid_icon,auto_launch}]`. Loaded once from `settings.json`, written atomically (tmp + rename), emits `settings-changed`. **All persistent data is centralized** in one Local AppData folder (`%LOCALAPPDATA%\<identifier>\`): `settings.json` + sibling `.icons\` icon cache; migrated from the old Roaming config dir on first run.
- **Frontend `settings/SettingsContext.tsx`** — `SettingsProvider` wraps the app; `useSettings()` → `{ settings, ready, update(mutator) }`. **Settings hydrate asynchronously** after the first await `get_settings`, so mount-time behavior must gate on `ready` (true once persisted settings have loaded). Updates are optimistic + persisted in the background; a `settings-changed` listener keeps the context in sync if Rust mutates the file. Adding a setting = add to Rust `Settings` + mirror in TS `Settings`/`DEFAULT_SETTINGS`, then read/write via `useSettings()`. Bump `version` only if a migration is needed.

## Apps tab
- Curated, persisted list (`app_shortcuts` in settings). Discovered from the **Start Menu** (recursively walks `%PROGRAMDATA%\Microsoft\Windows\Start Menu\Programs` and the user equivalent for `.lnk`), **Microsoft Store** (`Get-StartApps` via PowerShell with `CREATE_NO_WINDOW`, only entries with AUMID — i.e. AppID contains `!`), and **Steam** (registry `HKCU\Software\Valve\Steam` + `appmanifest_*.acf` files, with `libraryfolders.vdf` parsed by a small VDF tokenizer; `kind`: `exe` | `store` | `steam`; `source`: `""` | `Store` | `Steam`). Browse any `.exe`/`.lnk` from the file dialog. Launching branches by kind: store → `IApplicationActivationManager::ActivateApplication` (COM, hand-declared vtable — `windows-sys` ships the CLSID but no interfaces; **not** `explorer shell:AppsFolder\<AUMID>`, which would start Explorer and raise the desktop when `auto_immersive` is on; falls back to the old AppsFolder path only when the desktop isn't replaced), steam → `steam://rungameid/<appid>`, else `ShellExecuteW`. Apps can be **renamed** via `display_name` (empty/null = original name).
- **`launch_app` is async + bounded.** The dispatch is wrapped in `launch_with_timeout` (5 s, `std::thread::spawn` + `recv_timeout` — abandons the worker on timeout since you can't kill an in-process Win32 RPC). Without this, Store / `ms-settings:` / `steam://`-via-packaged-broker launches hang indefinitely under Auto Immersive Mode (Explorer never started → no broker infrastructure → DCOM activation never returns) and the user sees a frozen UI with no feedback. The frontend `launch()` callsite used to `// ignore launch errors` silently; it now toasts `String(e)` so the user sees the friendly message ("This app needs Windows' desktop shell — exit Immersive Mode to launch it"). Mirrors the `bounded_wait` pattern used by `moonlight_quit` / `wifi_scan` / `bluetooth::*`.
- **Icon resolution** (priority): custom file (copied into `.icons`) → pinned SteamGridDB icon (also cached into `.icons`) → SteamGridDB by app name (network, requires key) → extracted desktop icon from the exe/.lnk → gradient auto. All results are written to the disk cache so reloads are offline.
- **`app_icon`** command: serves from the cache if present; otherwise tries SteamGridDB by name (when a key is set) and falls back to `extract_icon_png` (which resolves `.lnk` targets so Windows' shortcut-arrow overlay doesn't show). Returns a `data:image/png;base64,…` URI.
- **`cache_steamgrid_icon(url)`** downloads an SGDB icon into `.icons` and returns its local path so the URL becomes offline-safe.
- **`import_app_icon(src)`** copies a custom image into `.icons` so the icon survives the original file moving.
- **`clear_cached_icon(path)`** removes the cached PNG so "Use Desktop Icon" can re-extract.
- **`clipboard_icon_hint`** classifies the clipboard into `image` / `url` / `base64` / `text` / `none` so the context-menu action can be grayed out when nothing usable is there. **`clipboard_icon_import`** extracts the actual image (raw clipboard image, `data:` URI, https URL, or raw base64) and saves it as PNG into `.icons`.
- Context menu per app: **Rename…**, **Search SteamGridDB**, **Use Custom Icon**, **Copy From Clipboard** (disabled when nothing usable), **Clear custom icon** (when one is set), **Use Desktop Icon**, **Autolaunch with Auto Immersive Mode** (hidden entirely when `auto_immersive === false`), **Remove**.
- **Per-app Autolaunch** (`app_shortcuts[*].auto_launch: bool`, `#[serde(default)]` for backward compat). Rust `launch_autolaunch_apps` command snapshots the flagged list under the settings lock and runs the launches on `spawn_blocking`, staggered 250 ms apart. One bad shortcut doesn't block the rest. Frontend fires it from `App.tsx` in the same `booted_as_shell` branch as the Immersive auto-entry, gated on `autoEntered` ref so it runs at most once per process — mirrors the existing `enterImmersive()` pattern next door. The row is hidden when `auto_immersive` is off because the toggle is a no-op then (the shell stub never fires).
- The installed picker uses the reusable **`ui/FilterList.tsx`** (search + source chips + A↔Z / Z↔A sort).
- App tiles: `p-3` wrapper, full-bleed `aspect-square` image with `rounded-2xl` mask, label below. Selection = `scale-[1.08]` + `bg-(--color-accent-soft)` shadow on the wrapper (handled inside `AppsView` via an internal `focusIdx` driven by the grid's keyboard handler).

## Design / UI conventions
- **Tokens** in `src/styles.css` `@theme`: `--color-{bg,surface,surface-2,border,muted,text,accent,accent-2,danger}` plus derived alpha tokens `accent-soft`, `surface-ghost`, `overlay`, `overlay-soft`, `muted-soft`. Use tokens for all colors (no hardcoded `black/x` opacity). The dark palette is the base; `[data-theme="light"]` re-binds the surface tones (bg / surface / surface-2 / border / muted / text + alpha tokens) for light mode. `--color-accent` is set at runtime by `ThemeProvider` from `settings.appearance`, so it's theme-independent.
- Root font-size `17px` for Big-Picture sizing. Theme is user-selectable via Settings → Appearance (Dark / Light / Auto) and Auto live-follows the Windows app-mode setting (`HKCU\...\Themes\Personalize\AppsUseLightTheme`, polled every 3s, pushed via `windows-theme-changed` Tauri events).
- **Shared `ui/` primitives:** `Toggle`, `Row`, `Section`, `SectionLabel`, `Select`, `Segmented`, `Modal`, `Toast`, `Input`, `ContextMenu`, `FilterList`, `Button`, `Card`, `Prompt`, `WifiModal`, `AudioModal`, `BatteryModal`, `StatusPill`, `IconTile`, `Slider`, `LoadingChip`, `BatteryIcon`, `WifiIcon`, `SpeakerIcon`. Reuse these — no duplicate local components. The three "Icon" components (Battery/Wifi/Speaker) follow the same pattern: a level-based dimmed base + an overlay glyph for state (charging / connected / volume). `LoadingChip` is the spinner+label used wherever a `Row` right-slot has an in-flight async load. `SectionLabel` is the shared uppercase label used inside modals (Audio / Battery).
- `Modal` default padding `p-5`; supports `title`/`subtitle` (in-panel header + X) and `width`. Closes on Escape and on overlay `onMouseDown` (with the panel itself stopping propagation so dragging out of the panel doesn't close it).
- `ContextMenu` is a single shared singleton: `useContextMenu()` writes to a module-level store, `<ContextMenuHost/>` (mounted once in `App.tsx`) renders whatever the store holds. Outside-click, scroll, blur, Escape all close it. Items support `label` / `icon` / `danger` / `disabled`.
- `Toast` is a small bottom-centered pill, no copy button. Auto-dismiss is owned by the caller (see `AppsView`, `MoonlightView`).
- Icons: Phosphor, `weight="bold"` everywhere (e.g. `<Play size={15} weight="fill" />` only where a filled glyph is intentional).
- Single-instance Tauri (second launch focuses the existing window).

## Build / run
- `npm install`
- `npm run tauri dev` (hot reload; Rust auto-recompiles on `src-tauri` change).
- `npm run tauri build` (production bundle; runs `tsc && vite build` first).
- ARM64 cross-build: `scripts/build-arm64.ps1 -Destination 'Z:\'` loads the MSVC cross env (`vcvarsall.bat x64_arm64`), cargo-cleans stale metadata, runs `npm run tauri build -- --target aarch64-pc-windows-msvc`, and copies the resulting `tauri-app.exe` to the destination as `moonblast.exe`. MSI + NSIS installers are produced as side effects (not disabled by the script). `ureq` uses rustls/`ring`; `ring` requires **clang** for ARM64 (`winget install LLVM.LLVM` once) — no OpenSSL/Perl needed.
- Rust compiles via MSVC; needs VS 2022 C++ tools + WebView2.
- Tauri plugins used: `tauri-plugin-dialog` (file picker), `tauri-plugin-opener`, `tauri-plugin-single-instance`.
- The codebase is purely **CLI-based** for Moonlight; keep it that way (no in-process protocol implementation).
